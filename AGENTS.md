# AGENTS.md — WizCast Frontend (`frontend/`)

This file is **authoritative for the `frontend/` submodule** — the Host + contestant client. The root `AGENTS.md` governs the workspace as a whole: cross-repo boundaries, the WebSocket message contract, shared conventions, and agent decision-making. Where a fact is workspace-wide (the message protocol, the capability inventory, the tech stack source), the root `AGENTS.md` and its referenced sources win; this file owns the frontend-specific detail.

Git operations (commit, push, branch) must happen **inside this submodule**, not at the workspace root.

## Commands

Run all commands **inside the `frontend/` directory**:

```bash
bun dev               # Vite dev server (fixed port 1420 — Tauri requirement)
bun tauri dev         # Tauri app with dev server
bun run build         # tsc && vite build — the real gate (typecheck is part of it)
bun lint              # Biome check --write (biome.json)
bun format            # Biome format --write
```

- **Use `bun run build`, not bare `bun build`.** The `build` script is `tsc && vite build`, so it typechecks first and type errors block it. Bare `bun build` invokes Bun's own bundler and does **not** run the `package.json` script or `tsc`.
- `bun tauri dev` and `bun dev`: the Vite dev server port is fixed at **1420**, required by Tauri's `beforeDevCommand` (`bun dev`) and `devUrl` (`http://localhost:1420`) in `src-tauri/tauri.conf.json`.
- No test runner is configured. There are no test files.

## Architecture & Conventions

- **Feature-first structure.** Feature code lives under `src/features/<feature>/` (components + hooks per feature); cross-cutting code lives under `src/shared/` (components, hooks, services).
- **Path alias** `@/*` maps to `src/*` (configured in `tsconfig.json` and `vite.config.ts`).
- **Imports:** shared code via `@/shared/...`; feature code via `@/features/<feature>/...`.
- **State:** React Context (`GameProvider`, `StoreProvider`).
- **File naming:** kebab-case for file names; PascalCase for components/types; camelCase for functions and variables.
- **Formatting/linting:** Biome v2 (`biome.json`) — 2-space indent, 140-char line width, single quotes, semicolons, trailing commas. `src/routeTree.gen.ts` and `src-tauri/` are excluded from Biome's includes.

## Local Rules

- **Never hand-edit `frontend/src/routeTree.gen.ts`** — it is generated by TanStack Router.
- **Abstract Tauri and browser APIs behind `src/shared/services/`** — components and hooks SHALL NOT import `@tauri-apps/*` plugins directly. (See `src/shared/services/status-bar.ts` and `src/shared/hooks/useStatusBarStyle.ts` for the pattern.)

## Frontend-Specific Conventions

- **TypeScript strict mode** is on; `noUnusedLocals` and `noUnusedParameters` are enforced.
- **Mantine CSS** uses `postcss-preset-mantine` with `postcss-simple-vars` for breakpoint variables.
- **i18n:** i18next + react-i18next, locales `en` and `de`.
- **Persistence:** Tauri Plugin Store (`games.json` in the app data dir).
- **Geolocation:** `NSLocationWhenInUseUsageDescription` is declared in `src-tauri/Info.ios.plist`; the geolocation plugin is registered in `src-tauri/src/lib.rs`.
- Formatting follows the workspace convention: trailing commas, single quotes, 140-char print width (see `biome.json`).

## iOS Shell Notes

The iOS shell is a Tauri 2 app whose lockfile resolves the scene-capable Tauri 2.12 / tao 0.37 line. The notes below describe the current iOS scene-lifecycle, safe-area, and status-bar behavior. Do not hand-edit any generated file under `src-tauri/gen/apple/` — it is regenerated on build.

### Scene manifest — `src-tauri/Info.ios.plist`

`src-tauri/Info.ios.plist` declares a static `UIApplicationSceneManifest` so the bundle adopts the UIKit scene-based lifecycle (required to launch under the iOS 27 SDK):

- `UIApplicationSupportsMultipleScenes` = `true`
- `UISceneConfigurations → UIWindowSceneSessionRoleApplication` = one configuration dict with:
  - `UISceneConfigurationName` = `TaoScene`
  - `UISceneDelegateClassName` = `TaoSceneDelegate`

The file also declares the status-bar appearance keys:

- `UIViewControllerBasedStatusBarAppearance` = `true`
- `UIStatusBarStyle` = `UIStatusBarStyleDefault`

(and `NSLocationWhenInUseUsageDescription` for geolocation).

Tauri **merges `Info.ios.plist` into the generated bundle `Info.plist` at build time**, so this survives `bun tauri ios build` and the `release.sh` pipeline. The generated `src-tauri/gen/apple/WizCast_iOS/Info.plist` has no scene manifest and **MUST NOT be hand-edited** (nor should anything else under `src-tauri/gen/apple/**`).

### Entry point and single-window behavior — `src-tauri/src/lib.rs`

The entry point uses `.build(generate_context!()).run(|app, event| …)`. Under `#[cfg(target_os = "ios")]` the run callback handles `RunEvent::SceneRequested` via `present_scene_window`:

- It derives a window label of the form `scene-<identifier>` from `scene.session().persistentIdentifier()`.
- It returns early if a window with that label already exists, so a request for the *same* scene never opens a duplicate window.
- Otherwise it builds a window loading `index.html` (`WebviewUrl::App("index.html")`).

`UIApplicationSupportsMultipleScenes` stays `true` because the static manifest is what the iOS 27 launch validator inspects; the handler ensures a requested scene presents the normal application window rather than a blank one.

### Capability window scope — `src-tauri/capabilities/default.json`

The `default` capability scopes `windows` to `["main", "scene-*"]`, so a window presented for a requested scene receives the same permissions as `main` (core, opener, store, geolocation, fs).

### Safe-area layout

- `index.html` sets `viewport-fit=cover` in the viewport meta tag and `html { background-color: var(--mantine-color-body); }`.
- `src/routes/__root.tsx` applies `env(safe-area-inset-*)` through Mantine's `--app-shell-*` variables: the header height is `calc(60px + env(safe-area-inset-top, 0px))`, and the navbar/main padding add the corresponding insets.
- `src/shared/components/Header/Header.tsx` adds the top/left/right insets to Mantine's `--mantine-spacing-sm` padding.
- All insets use guarded `env(…, 0px)` / `var(…, 0rem)` fallbacks, so desktop and browsers without inset support are unaffected. These inline `calc()` overrides depend on Mantine CSS variables and should be revisited on major Mantine upgrades.

### Status bar

- `src/shared/services/status-bar.ts` exposes `setStatusBarStyle(scheme)` with `StatusBarScheme = 'auto' | 'light' | 'dark'`; it dynamically imports `@tauri-apps/api/core` and invokes the `set_status_bar_style` command, swallowing failures so it is inert outside Tauri and on non-iOS platforms.
- `src/shared/hooks/useStatusBarStyle.ts` reads the raw Mantine preference via `useMantineColorScheme()` and calls the service in an effect; it is wired into the root layout in `src/routes/__root.tsx`.
- The Rust `set_status_bar_style` command is a no-op outside iOS; on iOS it applies the scheme to the window and root view controller on the main thread. `"light"` maps to `UIUserInterfaceStyle::Light`, `"dark"` to `Dark`, and `"auto"` to `Unspecified` so the webview and status bar keep following the system appearance.

## Release Pipeline

```bash
zsh release.sh [--major | --minor]
```

Bumps the version in `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`, builds iOS via `bun tauri ios build`, uploads to App Store Connect via `xcrun altool`, and commits. Requires `jq`, `xcrun`, and `APPLE_API_KEY` / `APPLE_API_ISSUER` environment variables.
